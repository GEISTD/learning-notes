1 · 机器学习基础

1.1 三种学习范式

范式数据形态典型任务例子
监督学习有标注（x → y）回归（连续值）、分类（离散类别）房价预测、垃圾邮件识别
无监督学习无标注聚类、降维、异常检测用户分群、PCA 降维
强化学习环境 + 奖励信号序列决策AlphaGo、RLHF 对齐、Agent 策略

1.2 训练的核心循环（一切模型通用）

for 每一批数据:
    预测  ŷ = model(x)          # 前向传播
    损失  loss = L(ŷ, y)         # 衡量"错得有多离谱"
    梯度  g = ∂loss/∂参数        # 反向传播：每个参数该往哪调
    更新  参数 -= 学习率 × g      # 沿负梯度走一小步
必懂概念：
损失函数
量化"预测有多错"的函数。回归用 MSE，分类用交叉熵
梯度下降
沿损失下降最快的方向更新参数。学习率太大震荡发散，太小收敛慢
过拟合
训练分高考试分低 = 背题了。解法：更多数据、正则化、早停、Dropout
欠拟合
训练考试都不行 = 模型太简单。解法：加参数、加特征、训更久
数据三分
训练集（学）/ 验证集（调参、早停）/ 测试集（最终考试，绝不参与训练）

1.3 评估指标

指标含义口诀
Accuracy全对的比例类别不均衡时会骗人（99% 负样本时全猜负也有 99%）
Precision 精确率预测为正的里面，真对多少"报出来的准不准"——宁可漏报不可误报时看它
Recall 召回率真为正的里面，找出了多少"该找的漏没漏"——宁可误报不可漏报时看它（如癌症筛查）
F1P 和 R 的调和平均两者要兼顾时的单一数字
混淆矩阵TP/FP/FN/TN 四格一切分类指标的源头
动手锚点（对应你的 S1）：用 NumPy 从零实现线性回归 + 逻辑回归 + kNN，手推 MSE 和交叉熵的梯度——这是本章节的全部实战载体。

2 · 深度学习基础

2.1 神经元与多层感知机（MLP）

一个神经元 = y = σ(Wx + b)：线性变换加非线性激活。激活函数是灵魂——没有它，多层网络叠加仍是线性变换，等于白叠。

激活函数公式/特点用途
ReLUmax(0, x)，简单高效不易梯度消失CNN/MLP 默认首选
Sigmoid压到 (0,1)，输出概率二分类输出层
Softmax压成和为 1 的概率分布多分类输出层、注意力权重
GELUReLU 的平滑版Transformer 内部（GPT/BERT）

2.2 主干网络架构演进

架构擅长核心机制代表
CNN图像（局部特征 + 平移不变）卷积核滑动共享权重、池化降维ResNet、YOLO
RNN/LSTM序列（旧方案）按时间步循环、隐状态传递已被 Transformer 大面积取代
Transformer文本、多模态、一切自注意力：任意两位置直接交互，可完全并行GPT、BERT、ViT、多模态大模型
自注意力一页话：每个 token 生成 Q（我在找什么）、K（我是什么）、V（我的内容）。用 Q 和所有 K 做点积算"相关度"，softmax 成权重，加权求和所有 V——每个词都能"看到"全句并按相关性吸收信息。Attention(Q,K,V) = softmax(QKᵀ/√d)·V，除以 √d 防止点积过大导致 softmax 饱和。

2.3 训练工程必备件

组件作用
BatchNorm / LayerNorm稳定各层输入分布，加速收敛（Transformer 用 LayerNorm）
Dropout训练时随机丢弃神经元 → 防过拟合
学习率调度预热（warmup）+ 余弦衰减；微调用小学习率（1e-5 ~ 5e-5）
早停 Early Stopping验证集损失不再下降就停 → 防过拟合
反向传播链式法则从输出层往回逐层算梯度（autograd 框架自动完成）
动手锚点（对应 S2/S3）：PyTorch 手写训练循环 + CIFAR10 CNN；再手写一遍 attention 公式并与 nn.MultiheadAttention 对数值。

3 · LLM 是怎么炼成的

3.1 从文本到数字：Tokenization 与 Embedding

Tokenizer
把文本切成 token（子词单元）。英文约 1 token ≈ 0.75 词，中文约 1 字 ≈ 1~2 token。所有模型按 token 计费、限上下文长度
Embedding
把 token 映射成高维向量（如 1536 维）。语义相近 → 向量距离近，这是语义检索/RAG 的数学基础
位置编码
注意力本身无序，需要注入位置信息（正弦编码 / RoPE 旋转位置编码）

3.2 训练三阶段

阶段做什么数据产出
预训练下一个词预测（自监督）数万亿 token 网络文本基座模型（Base）：会"续写"，不会"对话"
监督微调 SFT学会以助手身份对话人工写的高质量问答对会聊天的 Instruct 模型
RLHF / 对齐人类偏好强化：有用、诚实、无害人类对回答的排序打分最终发布的对话模型
关键推论（理解很多现象的钥匙）：LLM 本质是条件概率生成器——逐 token 预测下一个词。所以它：① 没有真正的"查数据库"能力 → 需要 RAG；② 知识截止在训练数据 → 需要联网/工具；③ 会一本正经编造 → 幻觉的根源；④ 温度参数控制采样的随机性。

3.3 两大流派与缩放定律

流派训练目标擅长代表
GPT 类（Decoder-only）预测下一个词生成、对话、代码 —— 当前主流GPT、Claude、Llama、Qwen、DeepSeek
BERT 类（Encoder-only）完形填空（双向）理解类任务：分类、检索、embeddingBERT、各类 embedding 模型

缩放定律（Scaling Law）：模型效果随「参数量 × 数据量 × 算力」按幂律提升——这是"大力出奇迹"的理论依据，也解释了为什么各家疯狂堆卡。涌现能力：规模跨过某个阈值后突然出现的能力（如推理、指令跟随）。

4 · LLM API 与调用（应用第一课）

4.1 一切应用的基础：Chat API 的形状

各家 API（OpenAI / Anthropic / 国产）形态高度趋同，核心是 messages 数组 + 三种角色：

response = client.chat.completions.create(
    model="qwen-plus",
    messages=[
        {"role": "system",    "content": "你是一个严谨的编程助教"},   # 设定身份与规则
        {"role": "user",      "content": "解释什么是过拟合"},          # 用户输入
        {"role": "assistant", "content": "过拟合是指……"},             # 历史回复（多轮对话=把历史全部带上）
        {"role": "user",      "content": "怎么解决？"}                 # 新一轮输入
    ],
    temperature=0.7,      # 随机性：0=确定性（提取/分类），1=发散（创意写作）
    max_tokens=1024,      # 输出上限，也是成本上限
    stream=True           # 流式输出，逐 token 返回，体感更快
)
必须建立的成本意识：
计费
按 token 计费，输入 + 输出分开计价；输入通常更便宜，输出更贵
上下文窗口
输入+输出共享窗口（如 128K）。对话越长越贵、越慢，且"中间信息容易被忽略"（lost in the middle）
多轮对话本质
API 是无状态的——"记忆"靠你把历史 messages 每次全量重发。这是理解 Agent 上下文管理的起点
系统提示词
system 的优先级高于 user，适合放身份、规则、输出格式约束

4.2 Function Calling：让模型"动手"

LLM 只会生成文本，要让它查数据库、调接口、执行代码，就通过工具调用：你声明工具的名称、功能描述、参数 JSON Schema → 模型在需要时返回"我要调用某工具+参数" → 你的代码执行它 → 把结果喂回去 → 模型继续。

tools = [{
  "type": "function",
  "function": {
    "name": "get_weather",
    "description": "查询指定城市的实时天气",   # 描述写得好坏直接决定模型会不会用对
    "parameters": {
      "type": "object",
      "properties": {"city": {"type": "string"}},
      "required": ["city"]
    }
  }
}]
# 返回里若出现 tool_calls → 你执行 get_weather("成都") → 把结果作为
# {"role":"tool", "content":"晴 26℃"} 追加进 messages → 再次请求
关键认知：模型从不真正执行任何东西——它只输出"调用意图"。执行永远发生在你的运行环境里。这条认知是理解下一章 Agent 的地基。

5 · Prompt 与 Context Engineering

5.1 Prompt Engineering 核心技法

技法怎么做适用
Zero-shot直接下指令简单任务、强模型
Few-shot给 2~5 个输入输出示例格式对齐、风格模仿，性价比最高的稳定器
CoT 思维链"请一步步思考"数学、逻辑、多步推理
角色设定system 里给身份与约束所有正式应用的基础
结构化输出要求 JSON / 明确 schema + 示例程序要解析模型输出时必须
分隔符隔离用 ```或XML标签包裹用户内容防注入、防混淆指令与数据

5.2 Context Engineering：Prompt 的升级版

单次提示怎么写只是术；Context Engineering 管的是"模型在每一步到底能看到什么"——在有限的上下文窗口里，动态组装出最优的信息组合：

System 规则 + 检索到的知识(RAG) + 工具结果 + 对话历史 + 记忆 → 上下文窗口
策略说明
历史裁剪 / 滑动窗口只保留最近 N 轮，久远信息压缩成摘要
上下文压缩长文档 → 摘要；多轮工具结果 → 只留结论
按需注入信息不预塞，Agent 需要时再通过工具/检索拉取（Skill 与 MCP 的动机）
位置放置关键约束放开头和结尾（中间最容易被忽略）
一句话区分：Prompt Engineering = 写好这一条消息；Context Engineering = 设计模型整个"视野"。Agent 系统的核心工程量就在后者。

6 · Agent 全解（应用层的核心主角）

6.1 定义

Agent = LLM（大脑）+ 工具（手脚）+ 循环（生命）+ 记忆（经验）。
普通 LLM 调用是"一问一答"；Agent 是让模型在循环中自主规划 → 调用工具 → 观察结果 → 决定下一步，直到完成目标。区别的本质：从"回答问题"升级为"完成任务"。

6.2 Agent 主循环（ReAct 范式）

# 所有 Agent 框架的内核都是这个循环，手写一遍胜过看十个框架
messages = [system(目标+可用工具说明), user(任务)]
while True:
    resp = llm(messages)                    # 思考 Reason
    if resp.tool_calls:                     # 决定行动 Act
        results = [execute(t) for t in resp.tool_calls]   # 环境执行
        messages += [resp, tool_results]    # 观察结果 Observe
    else:
        return resp.content                 # 无需工具 → 给出最终答案

6.3 Agent 四大件

组件职责常见实现
规划 Planning把大任务拆成子步骤，决定调用顺序CoT、任务清单、ReAct、Plan-and-Execute
工具 Tools突破"只会生成文本"的限制：搜索、代码执行、API、文件系统Function Calling、MCP
记忆 Memory短期 = 上下文窗口内的历史；长期 = 外部存储，跨会话保留向量库、数据库、摘要文件（如 CLAUDE.md）
反思 Reflection检查自己的输出、发现错误、重试改进自评 prompt、测试反馈回路、多轮自我修正

6.4 多 Agent 协作

单个上下文装不下复杂任务时，拆成多个角色（规划者 / 执行者 / 评审者），各自维护自己的上下文，通过消息传递协作——本质是用分工换上下文空间，代价是通信开销与误差传递。你的计划里 S6 只需做到：能用 Function Calling 完成多步任务。

Agent 的真实短板（面试加分点）：错误会累积（一步错步步错）、成本随循环次数膨胀、可能陷入死循环（必须设最大步数）、工具描述不清时选错工具。所以生产级 Agent 必须有：步数上限、成本预算、人工介入点（human-in-the-loop）、全程日志。

7 · Harness / Skill / Rule / Memory / MCP —— Agent 生态五件套

这一章是你点名要的概念。它们都是围绕"把裸 LLM 变成可靠 Agent"出现的工程概念。

7.1 Harness（智能体运行框架 / 脚手架）

是什么
包裹模型的整个执行环境：主循环、工具的注册与执行、上下文组装、权限控制、日志——模型之外的一切代码
类比
模型是发动机，Harness 是整辆车：底盘、油路、方向盘、仪表盘。发动机再强，没底盘开不动
例子
Claude Code、OpenAI Codex CLI、开源的 agent loop 框架，本质都是 harness
为什么重要
同一个大模型，套上不同的 harness 表现天差地别——上下文怎么组装、工具怎么给、错误怎么反馈决定了 Agent 的上限。这就是"模型能力 ≠ 产品能力"的原因

7.2 Skill（技能包）

是什么
把某个领域的知识、流程、脚本打包成的可复用模块（通常是一个带说明文档的文件夹：SKILL.md + 资源文件）。Agent 平时只看到技能清单（名字+描述），需要时才把完整内容加载进上下文
解决什么
上下文有限——不可能把所有专业知识常驻上下文。Skill = "按需加载的专家手册"
类比
员工入职时只看岗位目录，接到具体任务才翻对应岗位的详细 SOP 手册
与工具的区别
Tool 是"能做某动作"（调 API）；Skill 是"懂某领域怎么做好"（知识+流程+可含脚本）。Skill 内部可以调用工具

7.3 Rule / Rules（规则）

是什么
常驻的、全局性的行为约束与项目约定，每次请求都注入 system 上下文（如 Claude Code 的 CLAUDE.md、Cursor 的 .cursorrules、通用的 AGENTS.md）
典型内容
"本仓库用 TypeScript 严格模式""commit 用中文""改代码前先读对应文件""永远不要 push 到 main"
与 Skill 区别
Rule = 每次都在场的"公司规章"；Skill = 按需取用的"专业手册"

7.4 Memory（记忆）

类型载体生命周期
短期记忆当前上下文窗口内的 messages本次会话
长期记忆外部存储：向量库 / 文件 / 数据库，需要时检索注入跨会话持久
项目记忆仓库内的记忆文件（如 CLAUDE.md 中"用户偏好"段落）跟随项目

7.5 MCP（Model Context Protocol）

是什么
Anthropic 提出并成为事实标准的开放协议：统一"模型 ↔ 外部工具/数据源"的接入方式。MCP Server 暴露 tools（可调用动作）/ resources（可读数据）/ prompts（预设模板），任何支持 MCP 的客户端都能即插即用
类比
工具界的 USB-C：以前每个 Agent × 每个工具都要写一次私有对接，现在都插同一个协议口
价值
生态复用——社区写好的 MCP Server（GitHub、数据库、浏览器…）所有客户端共享；企业内部系统只需写一次 Server 就能接入所有 AI 工具

7.6 五件套关系图

Harness包裹运行 →LLM
Rule 常驻约束 Skill 按需加载 Memory 跨会话存取 MCP 标准接工具
↑ 全部由 Harness 负责在正确的时机组装进上下文

8 · RAG 检索增强生成

8.1 解决什么问题

模型知识有截止日期、不含私有数据、长上下文贵且慢。RAG = 先从你的资料里"检索"相关片段，塞进上下文，再让模型"生成"有依据的回答——给外挂知识库，顺便用引用压制幻觉。

8.2 全链路（你的 S4+S5 主项目）

【索引阶段·离线】文档解析 → 分块 chunking（固定长度+overlap+句子边界）
        → embedding 模型向量化 → 存入向量库（FAISS/Chroma/pgvector）
【查询阶段·在线】用户问题 → 向量化 → 相似度检索 Top-K
        → （可选）重排 rerank → 拼进 prompt（带来源）→ LLM 生成 → 附引用
环节关键决策点
分块chunk 太小丢上下文、太大稀释相关性；中文 300~500 字 + 10~20% overlap 是常用起点
Embedding 选型中文场景选中文优化的 embedding 模型；维度越高信息越丰但存储越贵
检索余弦相似度 Top-K；混合检索（关键词 BM25 + 语义向量）通常更稳
重排 Rerank用交叉编码器对 Top-20 精排出 Top-5，显著提升精度，代价是延迟
评估检索侧 recall@k / MRR；生成侧 faithfulness（答案是否忠于检索内容）、answer relevance。没有评估的 RAG = 玄学调参
RAG vs 微调 vs 长上下文：知识频繁更新/私有 → RAG（便宜灵活）；改变行为风格/领域格式 → 微调；文档就几十页 → 直接塞长上下文。三者可组合，RAG 是 AI Engineer 岗位第一高频技能。

9 · 幻觉、评估与安全

9.1 幻觉（Hallucination）

成因
模型的本质是"预测统计上合理的下一个词"——它优化的是"像"，不是"真"。训练数据错误、知识缺失、采样随机性都会产生流利但错误的输出
缓解
① RAG 让答案有据可查；② 要求输出引用来源；③ 温度调低；④ 让模型先说"不知道"再回答；⑤ 关键场景接规则校验/人工审核；⑥ 高风险领域换用带推理验证的模型

9.2 评估（Evals）—— AI 工程的分水岭

方法做法成本
金标数据集人工标注 问题-标准答案 对，跑批算指标标注贵，结果最可靠
LLM-as-Judge让强模型按 rubric 给输出打分便宜可扩展，注意评委偏差
规则/单元测试格式校验、关键词必须出现、代码能否运行最便宜，覆盖面窄
在线指标用户点赞率、重试率、人工接管率真实但滞后
铁律：改 prompt / 换模型 / 调参数，必须在评估集上对比前后，不靠"我感觉变好了"。"会建评估"是区分玩具项目与工程项目的分水岭。

9.3 安全三件事

Prompt 注入
恶意指令藏进"数据"里（网页/文档/用户输入）劫持模型——防御：分隔符隔离、权限最小化、工具白名单、输出过滤
越狱 Jailbreak
角色扮演、编码伪装等绕过安全对齐——厂商层防御为主，应用层做输入输出双向审核
数据安全
API Key 走环境变量绝不硬编码；私有数据发第三方 API 前想清楚合规；敏感场景考虑本地部署开源模型

附录B · 面试速答 20 问

1. LLM 是怎么工作的？
本质是基于 Transformer 的下一个 token 概率预测器：预训练学语言规律 → SFT 学对话 → RLHF 对齐人类偏好。生成时逐 token 采样。
2. Transformer 为什么取代 RNN？
自注意力让任意两个位置直接交互且可完全并行训练，解决了 RNN 的长程依赖与串行慢两大问题。
3. Attention 公式及 √d 的作用？
softmax(QKᵀ/√d)·V；除以 √d 防止维度大时点积过大、softmax 进入饱和区导致梯度消失。
4. GPT 和 BERT 的区别？
GPT 是 Decoder-only 自回归生成，擅长生成；BERT 是 Encoder-only 双向理解，擅长分类/检索/embedding。
5. 为什么会幻觉？怎么缓解？
模型优化"统计上像"而非"事实上真"。缓解：RAG+引用、低温、允许说不知道、规则校验、人工审核。
6. RAG 的完整流程？
索引：解析→分块→embedding→入库；查询：问题向量化→Top-K 检索→重排→拼 prompt→生成附引用。检索质量决定上限。
7. RAG vs 微调怎么选？
知识问题（要新、要私有）用 RAG；行为/风格/格式问题用微调；两者可组合。RAG 便宜灵活可解释，微调改变模型本身。
8. Agent 和普通 LLM 调用的区别？
Agent 有循环：规划→调工具→观察→再决策直到完成目标，从"回答问题"升级为"完成任务"。
9. 描述 ReAct 循环。
Reason（模型思考该做什么）→ Act（发起工具调用）→ Observe（把执行结果喂回上下文）→ 循环直到无需工具输出答案。
10. Function Calling 的执行者是谁？
模型只输出"调用什么+参数"的结构化意图，真正的执行永远发生在调用方的运行环境，结果再喂回模型。
11. 什么是 Harness？
包裹模型的执行框架：主循环、工具注册执行、上下文组装、权限与日志。模型是发动机，Harness 是整车——同模型不同 Harness 表现差异巨大。
12. Skill 和 Tool 的区别？
Tool 是一个可执行动作（调 API）；Skill 是按需加载的领域知识+流程包（可内含脚本与工具用法），解决专业知识占上下文的问题。
13. Rule（如 CLAUDE.md）起什么作用？
常驻注入的全局约束：代码规范、工作流约定、禁区。与 Skill 的"按需加载"相对，Rule 是"每次都在"。
14. MCP 是什么，解决什么问题？
模型连接外部工具/数据的开放协议，M×N 对接问题变 M+N——一次实现处处可用，工具界 USB-C。
15. 多轮对话的"记忆"是怎么实现的？
API 无状态，靠每次全量重发历史 messages；长了就裁剪/压缩/摘要，跨会话记忆存外部库按需检索注入。
16. Temperature 设 0 会完全确定吗？为什么分类任务要设 0？
趋近确定性（硬件与实现仍有微小随机）。分类/提取要稳定结构所以设 0；创意生成调高。
17. 什么是 Prompt 注入？怎么防？
恶意指令藏进被处理的数据中劫持模型。防御：分隔符隔离数据与指令、最小权限、工具白名单、输出校验。
18. 怎么评估一个 LLM 应用的好坏？
金标数据集算指标 + LLM-as-Judge 按评分规则打分 + 规则测试 + 在线指标；任何改动必须在评估集上对比，拒绝体感。
19. 上下文越长越好吗？
不。成本与延迟随 token 线性涨，且存在 lost-in-the-middle；工程上讲究"每一步只注入必要信息"（Context Engineering）。
20. 生产级 Agent 必须有哪些保护？
最大步数限制、成本预算、超时与重试、人工介入点、全程日志与评估——防止死循环烧钱与错误累积。
