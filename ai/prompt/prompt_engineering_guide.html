什么是 Prompt Engineering

基础概念

Prompt（提示词）就是你给 AI 说的话。Prompt Engineering（提示词工程）就是研究"怎么跟 AI 说话，才能让它干得更好"的学问。

一句话理解
AI 就像一个能力极强但不会读心术的实习生。你说得越清楚、越具体，它做得越好。Prompt Engineering 就是教你怎么把需求说清楚。

为什么要学 Prompt？

效率提升 10 倍
好的 prompt 一次出结果，差的 prompt 改十遍都不对
质量可控
你能决定输出的格式、深度、风格，而不是碰运气
省钱省 token
精准的 prompt 减少来回对话，降低 API 调用成本
职场核心技能
AI 时代，会用 AI 的人取代不会用的人

Prompt 的本质

清晰的指令 + 充分的上下文 + 明确的输出要求 = 高质量结果
📐

六大核心原则

基础必会
1. 明确具体，不要模糊
❌ "帮我写篇文章"
✅ "帮我写一篇 800 字的科普文章，主题是 WSL2 的网络原理，面向大学生，语言通俗"
2. 给角色，给身份
告诉 AI "你是谁"，它会自动切换到对应模式。
"你是一位有 10 年经验的前端架构师..."
3. 给示例（Few-shot）
举 1~3 个例子比描述 100 个字更管用。尤其是格式类需求。
4. 分步思考（CoT）
复杂问题让 AI "一步步想"，准确率大幅提升。
"请先分析问题，再给出方案"
5. 规定输出格式
要 JSON？要 Markdown 表格？要代码？明确说出来。
"输出格式：JSON，包含 name, age, email 三个字段"
6. 给约束条件
告诉 AI "不要做什么"。字数限制、风格要求、禁用内容等。
"不要超过 500 字，不要用专业术语"
记忆口诀：角上下分格约
角色设定 · 上下文 · 下达任务 · 分步思考 · 格式要求 · 约束条件

经典 Prompt 框架

结构化方法

业界总结了很多好用的 Prompt 结构模板，照着填就行，不容易漏信息。

1. CRISPE 框架（最全面）

字母含义说明示例
CCapacity & Role（身份角色）你希望 AI 扮演什么角色"你是一位资深 Python 后端工程师"
RInput（输入）你要处理的原始信息"这是一段有 bug 的代码：..."
IInstruction（指令）具体要做什么"找出 bug 并修复，解释原因"
SOutput（输出格式）结果长什么样"输出格式：1. 问题分析 2. 修复代码 3. 注意事项"
PPersonality（风格）回答的语气风格"用简洁专业的语气，面向初学者"
EExample（示例）举例子说明"参考这个格式：..."
CRISPE 完整模板
你是一位【角色/身份】，拥有【X年经验/专业背景】。 【背景信息/输入内容】 请你完成以下任务： 【具体要做什么】 输出要求： 1. 【格式要求】 2. 【长度要求】 3. 【风格要求】 4. 【其他约束】 参考示例： 【示例1】 【示例2】

2. RTF 框架（简洁版）

字母含义说明
RRole（角色）AI 扮演的身份
TTask（任务）具体做什么
FFormat（格式）输出格式
RTF 简洁模板
你是【角色】。 请帮我【任务描述】。 输出格式：【格式要求】

3. CO-STAR 框架（复杂任务用）

字母含义说明
CContext（背景）任务的背景信息
OObjective（目标）要达成什么目标
SStyle（风格）输出的风格
TTone（语气）回答的语气
AAudience（受众）写给谁看的
RResponse（响应格式）输出的格式
怎么选框架？
简单任务（写封邮件、翻译一段话）→ 直接说，不用框架
中等任务（写文章、改代码）→ RTF 框架，简洁够用
复杂任务（产品方案、技术设计、研究报告）→ CRISPE / CO-STAR 框架，信息更全

核心技巧

提效神器

技巧 1：Few-shot Learning（给例子）

给 AI 看 1~3 个正确答案的例子，它就能学会你想要的模式。这是最有效的技巧之一。

❌ 不给例子 帮我把这些产品名改成英文： 1. 苹果手机 2. 华为笔记本
✅ 给例子 帮我把产品名翻译成英文，遵循以下格式： 示例： 输入：小米耳机 → 输出：Xiaomi Earbuds 输入：大疆无人机 → 输出：DJI Drone 现在翻译： 1. 苹果手机 2. 华为笔记本

技巧 2：Chain-of-Thought（思维链）

复杂问题让 AI "一步步思考"，准确率大幅提升。数学题、逻辑题、推理题特别管用。

❌ 直接问答案 一家店5个苹果卖10元，买8个多少钱？
✅ 让它一步步想 一家店5个苹果卖10元，买8个多少钱？ 请一步步分析并给出答案。
进阶：Self-Consistency（自洽性）
让 AI 用不同方法解同一道题，取出现次数最多的答案。可以提升难题正确率。

技巧 3：Role-play（角色扮演）

给 AI 一个明确的身份，它的回答质量会显著提升。

常用角色模板
# 编程类 "你是一位有10年经验的资深【前端/后端/算法】工程师，代码风格简洁规范，善于解释复杂概念" # 写作类 "你是一位资深【科技/商业/科普】作家，文章结构清晰，语言通俗易懂" # 学习类 "你是一位耐心的【数学/英语/编程】老师，擅长用简单的例子解释复杂概念，会循序渐进地引导学生" # 产品类 "你是一位有5年经验的产品经理，擅长用户需求分析和产品方案设计" # 翻译类 "你是一位专业的中英翻译，翻译准确流畅，保留原文语气和风格"

技巧 4：结构化输出

明确要求输出格式，让结果直接能用，减少二次整理。

常用格式要求
# Markdown 格式 "用 Markdown 格式输出，包含标题、列表、代码块" # JSON 格式 "输出严格的 JSON 格式，包含以下字段：name, age, skills（数组）" # 表格格式 "用表格形式输出，包含三列：名称、说明、示例" # 代码格式 "只输出代码，不要解释，不要用代码块包裹" # 分点输出 "分3点回答，每点不超过50字"

技巧 5：约束与边界

告诉 AI "不要做什么"，避免跑偏。

常用约束
- 字数："不超过500字" / "至少800字" - 受众："面向完全不懂技术的人" / "面向有3年经验的开发者" - 风格："用口语化的方式" / "用学术论文的严谨风格" - 内容："不要使用任何专业术语" / "必须包含代码示例" - 限制："只回答与SQL相关的问题，其他问题请说明无法回答" - 否定："不要用列表形式，请用连贯的段落"

技巧 6：迭代优化

第一次输出不满意很正常，关键是会"改 prompt"。

迭代三问
1. 哪里不满意？ → 太长？太短？方向偏了？格式不对？
2. 缺了什么信息？ → 是不是背景没说清楚？要求没讲明白？
3. 能不能给个例子？ → 把你想要的样子举出来，AI 秒懂
# 迭代示例 # 第1轮：太笼统 "帮我写一篇关于AI的文章" # 第2轮：加约束 "帮我写一篇500字的AI科普文章，面向高中生" # 第3轮：加结构 "帮我写一篇500字的AI科普文章，面向高中生。 结构：1.什么是AI 2.AI能做什么 3.怎么学习AI 语言要生动有趣，不要用专业术语" # 第4轮：给示例 "参考下面这篇文章的风格：[示例文章] 再写一篇关于大模型的科普文，500字左右"

常用 Prompt 模板

拿来就用
📝 写作类 - 文章/报告
你是一位资深的【领域】作家，擅长【风格】的写作。 请帮我写一篇关于【主题】的文章，要求： - 字数：约【X】字 - 受众：【面向什么人】 - 结构：【第1部分... 第2部分... 第3部分...】 - 风格：【生动有趣/专业严谨/通俗易懂】 - 语气：【口语化/正式/亲切】 请用 Markdown 格式输出，包含适当的标题和列表。
💻 编程类 - 代码编写
你是一位有【X】年经验的资深【语言/技术】工程师，代码风格简洁规范，注释清晰。 请帮我实现【功能描述】，要求： - 语言：【Python/Go/JS等】 - 输入：【输入是什么】 - 输出：【输出是什么】 - 注意事项：【边界条件、性能要求等】 请输出完整的可运行代码，并加上必要的注释。最后简要说明实现思路。
🐛 编程类 - Debug 查错
你是一位资深【语言】工程师，擅长排查 bug。 以下代码出现了问题： 【代码内容】 错误信息： 【报错信息】 请帮我： 1. 分析 bug 产生的原因 2. 给出修复后的完整代码 3. 说明如何避免类似问题
📚 学习类 - 知识讲解
你是一位耐心的【学科】老师，擅长用简单的例子解释复杂概念。 请帮我讲解【知识点】，要求： - 我目前的基础：【小白/有一定了解/有经验】 - 讲解深度：【入门/进阶/深入原理】 - 用【比喻/代码示例/画图/生活例子】的方式帮助理解 - 结构：先讲是什么 → 为什么需要 → 怎么用 → 注意事项 最后给我 3 道练习题检验理解程度，并附上答案。
🔍 研究类 - 信息调研
你是一位资深的研究分析师，擅长信息整理和对比分析。 请帮我调研【主题】，要求： - 调研范围：【时间/地区/领域限制】 - 输出结构： 1. 背景概述 2. 主要玩家/方案对比（用表格） 3. 优劣势分析 4. 发展趋势 5. 参考来源 请用客观、专业的语气，信息要有依据。
📋 翻译类 - 中英互译
你是一位专业的中英翻译，翻译准确流畅，保留原文的语气和风格。 请将以下内容翻译成【目标语言】： 【原文内容】 要求： - 风格：【正式/口语/文学/技术】 - 专业术语：【如有特定术语表请列出】 - 保留原文格式（如列表、加粗等）
🎯 总结类 - 内容提炼
请帮我总结以下内容： 【长文本/文章/会议记录】 要求： - 字数：【约X字 / 3-5句话】 - 保留：【关键数据/核心观点/行动项】 - 格式：【分点总结 / 一段式 / 表格】 请确保信息准确，不要添加原文没有的内容。
💼 面试类 - 模拟面试
你是一位资深的【岗位】面试官，有10年面试经验。 请对我进行模拟面试，要求： - 岗位：【目标岗位，如前端工程师】 - 难度：【初级/中级/高级】 - 面试流程：先问基础题，再问进阶题，最后问项目/场景题 - 每次只问 1 道题，等我回答后再给出点评和下一题 面试结束后给我整体评估： 1. 优势 2. 薄弱点 3. 改进建议 准备好了就开始吧！

场景实战

学以致用

场景 1：写代码

# ❌ 差的 prompt "帮我写个登录功能" # ✅ 好的 prompt "你是一位有5年经验的 Python后端工程师。 请用 Flask 实现一个用户登录接口，要求： 1. 使用 MySQL 数据库存储用户信息 2. 密码用 bcrypt 加密存储 3. 登录成功返回 JWT token 4. 包含输入验证（邮箱格式、密码长度） 5. 有适当的错误处理和 HTTP 状态码 项目结构： - app.py - 主程序 - models.py - 数据库模型 - auth.py - 认证逻辑 请输出完整可运行代码，并附上安装依赖的命令和测试方法。"

场景 2：学新技术

# ❌ 差的 prompt "教我学 Docker" # ✅ 好的 prompt "你是一位耐心的 DevOps 老师。我是一名前端开发，有基础的 Linux 知识，但完全没接触过 Docker。 请带我从零开始学习 Docker，要求： 1. 分阶段讲解，从入门到进阶 2. 每个知识点配一个动手练习 3. 用通俗的比喻解释概念，不要堆砌术语 4. 每阶段结束后给我一个小测验 先从第1阶段开始：Docker 是什么，为什么需要它，安装和第一个容器。"

场景 3：改简历

# ❌ 差的 prompt "帮我改改简历" # ✅ 好的 prompt "你是一位有5年经验的互联网行业HR，看过上千份简历。 以下是我的简历： 【简历内容】 我投递的岗位是【目标岗位名称】，岗位要求是： 【岗位JD内容】 请帮我： 1. 整体评价：我的简历匹配度如何？有哪些硬伤？ 2. 内容优化：哪些经历需要突出？哪些可以删减？ 3. 措辞优化：把平淡的描述改成有数据支撑、有冲击力的表述 4. 格式建议：排版和结构上有什么可以改进的？ 请用 STAR 法则优化我的项目描述。"

场景 4：做决策

# ❌ 差的 prompt "我该考研还是找工作？" # ✅ 好的 prompt "你是一位职业规划咨询师，有丰富的大学生职业指导经验。 我的情况： - 学校：【学校名称和层次】 - 专业：【专业名称】 - 年级：【大几】 - 成绩：【排名/绩点】 - 实习经历：【有/无，什么公司什么岗位】 - 技术栈：【会什么】 - 家庭经济情况：【是否需要尽快工作赚钱】 - 兴趣方向：【喜欢什么】 - 目标城市：【想去哪里发展】 请帮我分析考研和直接工作两种选择： 1. 各自的优缺点 2. 适合的人群 3. 未来 3-5 年的发展路径对比 4. 结合我的情况，你的建议是什么？为什么？ 请客观分析，不要给出绝对答案，帮我理清思路。"

常见错误与避坑

新手必看
错误表现正确做法
1. 太笼统 "帮我写个网站" 明确技术栈、功能、目标用户、页面结构等
2. 一次问太多 同时问 10 个不相关的问题 一个 prompt 聚焦一个任务，拆成多轮对话
3. 不给背景 直接抛问题，不说前因后果 提供必要的上下文：你是谁、为什么要做、约束条件
4. 不设边界 结果太长/太短/跑偏了 明确字数、格式、风格、不要做什么
5. 完全相信输出 AI 说什么都信 关键信息一定要验证，AI 会"幻觉"（编造假信息）
6. 不会迭代 一次不满意就放弃 好结果都是改出来的，3~5 轮迭代很正常
7. 怕写太长 觉得 prompt 越短越好 该长就长，信息越充分结果越好。长 prompt ≠ 费钱
8. 用问句不用陈述句 "你能帮我...吗？" 直接下达指令："请帮我..."
9. 忽略安全 把公司机密、密码发给 AI 敏感信息脱敏后再发，公司数据不要随便贴
10. 不验证代码 AI 写的代码直接用 一定要读一遍、测一遍，AI 会编不存在的 API
⚠️ AI 幻觉（Hallucination）
AI 会"一本正经地胡说八道"，编造不存在的事实、数据、引用。
应对方法：
1. 重要事实一定要交叉验证
2. 让 AI 给出参考来源（然后检查来源是否真实存在）
3. 代码一定要跑一遍，API 一定要查文档
4. 法律、医疗等专业领域的建议仅供参考

进阶技术

高级
1. 思维树（Tree of Thoughts）
不是让 AI 一条路走到黑，而是探索多条推理路径，评估后选最优的。适合复杂决策问题
2. 自我反思（Self-Refine）
让 AI 自己 critique 自己的输出，然后迭代改进。"请审视上面的回答，找出3个可以改进的地方并重写"
3. 专家混合（MoE Prompt）
让 AI 模拟多个专家讨论问题，"请模拟3位不同领域的专家讨论这个问题..."
4. RAG（检索增强生成）
把相关文档/资料先"喂"给 AI，让它基于你的资料回答，减少幻觉
5. 系统提示词（System Prompt）
在对话最开始设定全局规则，整个对话过程都生效。适合固定角色和输出风格
6. ReAct 框架
Reasoning + Acting，让 AI 边思考边行动（调用工具）。Agent 的基础原理

让 AI 自我改进的 Prompt

自我反思模板
请对你上面的回答进行批判性审视： 1. 有哪些不准确或可能有问题的地方？ 2. 有什么遗漏的重要信息？ 3. 逻辑上有没有漏洞？ 4. 有没有更好的表达方式？ 请根据以上审视，重写一个改进版。

专家辩论模板

多专家讨论模板
请模拟以下3位专家就【问题】展开讨论： 专家A：【身份和立场】 专家B：【身份和立场】 专家C：【身份和立场，中立裁判】 讨论规则： 1. 每位专家先发表自己的观点 2. 然后互相质疑和辩论 3. 最后由专家C总结共识和分歧点 请用对话形式输出。

高效 AI 工作流

方法论

四步工作法

第1步：明确需求
想清楚你到底要什么？目标是什么？输出给谁看？有什么约束？
第2步：写 Prompt
用 CRISPE 或 RTF 框架组织语言，角色+任务+格式+约束
第3步：评估输出
结果满意吗？哪里不对？缺了什么？多了什么？
第4步：迭代优化
告诉 AI 哪里不对，补充信息，让它改。重复 2~4 轮

问题参考回答
什么是 Prompt Engineering？ 提示词工程是研究如何设计和优化输入提示，使大语言模型输出更高质量、更符合预期结果的技术。核心是把人类需求清晰、准确地传达给 AI
写好 Prompt 的关键原则有哪些？ 1. 明确具体，不要模糊 2. 给角色身份 3. 给示例（Few-shot）4. 分步思考（CoT）5. 规定输出格式 6. 给约束条件。口诀：角上下分格约
什么是 Few-shot Learning？ 少样本学习，即在 Prompt 中给 AI 几个示例，让它理解任务模式后再执行。相比零样本（Zero-shot）效果更好，尤其是格式类和分类类任务
什么是 Chain-of-Thought（思维链）？ 让模型输出推理过程而不是直接给答案。通过"请一步步思考"等提示，引导模型展示中间推理步骤，能显著提升复杂推理题的准确率
Zero-shot、One-shot、Few-shot 的区别？ Zero-shot：不给例子直接提问；One-shot：给1个例子；Few-shot：给多个例子。例子越多效果通常越好，但也越费 token
什么是 AI 幻觉（Hallucination）？ 模型生成看似合理但实际错误的内容，比如编造不存在的事实、数据、引用。应对方法：交叉验证、让 AI 给出处、关键信息人工核实
System Prompt 有什么用？ 系统提示词在对话最开始设定，对整个对话生效。用来定义 AI 的角色、行为准则、输出风格等，是长期生效的"人设设定"
Prompt 越长越好吗？ 不是。信息充分很重要，但冗余信息反而可能干扰。原则：必要的信息不能少，无关的信息不要加。精准比冗长更重要
如何验证 Prompt 的效果？ 1. 定义评估标准（准确率、完整性、格式正确性等）2. 准备测试用例集 3. 同一任务多跑几次看稳定性 4. A/B 测试不同版本的 prompt
什么是 RAG？和 Prompt 什么关系？ RAG（检索增强生成）是先从知识库检索相关文档，再把文档拼到 Prompt 里，让 AI 基于给定资料回答。能减少幻觉、让回答更准确
温度（Temperature）参数是什么？ 控制输出随机性的参数。0~2 之间。越低越确定、越保守；越高越随机、越有创意。写代码选 0.1~0.3，创意写作选 0.7~1.0
什么是 Prompt 注入攻击？ 攻击者通过在输入中嵌入恶意指令，诱导 AI 忽略系统设定，执行非预期操作。防范方法：输入校验、输出过滤、角色隔离、用 delimiter 分隔用户输入
如何处理长文本任务？ 1. 分段处理：把长文本切成小块分别处理再汇总 2. 摘要压缩：先压缩再处理 3. RAG：检索相关片段再回答 4. 选择更大上下文窗口的模型
你觉得 Prompt Engineering 未来会消失吗？ 不会完全消失但会变化。随着模型理解能力提升，简单任务可能不需要精心设计 prompt 了。但复杂任务、专业领域、需要精确输出的场景，Prompt 依然重要。而且会从"写提示词"进化为"设计 AI 工作流"
举一个你用 AI 提升效率的例子 面试时说一个具体的例子：比如我用 AI 帮我写代码的单元测试，先给它函数签名和需求，它生成测试用例初稿，我再review补充。效率提升了大约3倍，而且覆盖率也更高
