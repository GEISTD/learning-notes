什么是 SQL

基础概念

SQL（Structured Query Language，结构化查询语言）是用来和数据库打交道的语言。你用它来增删改查数据、建表、管理用户等等。

数据库 (Database)
存储数据的"仓库"，一个数据库里可以有很多张表
表 (Table)
就像 Excel 表格，有行有列，用来存一类数据
行 (Row / Record)
一条数据记录。比如一个用户就是一行
列 (Column / Field)
一个字段。比如姓名、年龄、邮箱各是一列
MySQL
最流行的关系型数据库管理系统，开源免费
关系型数据库
数据以表格形式存储，表与表之间可以关联

举个例子

users 表（用户表）

idnameageemail
1张三20zhangsan@test.com
2李四22lisi@test.com
3王五19wangwu@test.com
SQL 关键词不区分大小写
SELECT * FROM users; 和 select * from users; 效果一样。
但习惯上关键词用大写，表名列名用小写，这样代码更易读。

SQL 基础语法

入门必读

SQL 四大分类

分类全称作用代表命令
DDL 数据定义语言 定义数据库结构（建库、建表） CREATE / ALTER / DROP
DML 数据操作语言 操作数据（增删改查） INSERT / UPDATE / DELETE / SELECT
DQL 数据查询语言 查询数据 SELECT（最复杂最常用）
DCL 数据控制语言 权限管理 GRANT / REVOKE
TCL 事务控制语言 管理事务 COMMIT / ROLLBACK

语法注意事项

  • 每条 SQL 语句以 ; 结尾
  • 关键词不区分大小写，但建议大写
  • 字符串用单引号包裹：'张三'
  • 注释：-- 这是注释（两个横杠加空格）或 # 这是注释
  • 多行注释：/* ... */
命名规范
表名、列名用小写字母和下划线，如 user_info，不要用中文、空格、特殊字符。

创建表（DDL）

DDL

建库建表完整流程

-- 1. 创建数据库 CREATE DATABASE learn_sql CHARSET utf8mb4; -- 2. 使用数据库 USE learn_sql; -- 3. 创建表 CREATE TABLE users ( id INT PRIMARY KEY AUTO_INCREMENT -- 主键，自增, name VARCHAR(50) NOT NULL -- 姓名，不能为空, age INT DEFAULT 0 -- 年龄，默认0, email VARCHAR(100) UNIQUE -- 邮箱，不能重复, created_at DATETIME DEFAULT CURRENT_TIMESTAMP -- 创建时间，默认当前时间 ); -- 4. 查看表结构 DESC users; -- 5. 查看所有表 SHOW TABLES; -- 6. 查看建表语句 SHOW CREATE TABLE users;

常用数据类型

类型说明示例占用
INT 整数（最常用） 1, 100, -50 4字节
BIGINT 大整数（存大数字用） 99999999999 8字节
DECIMAL(M,D) 精确小数（钱用这个！） 99.99 —
FLOAT / DOUBLE 浮点数（有精度丢失） 3.14159 4/8字节
VARCHAR(n) 可变长度字符串（最常用） 'hello' 最多n字符
CHAR(n) 固定长度字符串 'A' n字符
TEXT 长文本（最多65535字） 文章内容 —
DATE 日期 '2026-09-28' 3字节
DATETIME 日期时间 '2026-09-28 14:30:00' 8字节
TIMESTAMP 时间戳（自动时区） — 4字节
BOOL / BOOLEAN 布尔值（本质是 TINYINT） TRUE / FALSE 1字节
选类型的原则
够用就行，越小越好。存年龄用 TINYINT（-128~127）就行，不用 INT。存手机号用 VARCHAR(20)，不要用数字类型（手机号可能有 0 开头或 +86）。

修改表结构（ALTER）

-- 添加列 ALTER TABLE users ADD COLUMN phone VARCHAR(20); -- 修改列 ALTER TABLE users MODIFY COLUMN name VARCHAR(100); -- 重命名列 ALTER TABLE users CHANGE COLUMN name username VARCHAR(100); -- 删除列 ALTER TABLE users DROP COLUMN phone; -- 删除表 DROP TABLE users; -- 删除数据库 DROP DATABASE learn_sql;
DROP 是毁灭性操作！
DROP TABLE 和 DROP DATABASE 会直接删掉所有数据，没有回收站。操作前一定要确认！线上操作一定要先备份。

增删改查（CRUD）

最核心！

CRUD 就是增(Create)、查(Read)、改(Update)、删(Delete)的缩写，是数据库最基本的四种操作。

C = INSERT → R = SELECT → U = UPDATE → D = DELETE

1. 增：INSERT（插入数据）

-- 插入一行（指定列） INSERT INTO users (name, age, email) VALUES ('张三', 20, 'zhangsan@test.com'); -- 插入多行（批量插入，效率更高） INSERT INTO users (name, age, email) VALUES ('李四', 22, 'lisi@test.com'), ('王五', 19, 'wangwu@test.com'), ('赵六', 25, 'zhaoliu@test.com'); -- 全列插入（不推荐，列变了容易出问题） INSERT INTO users VALUES (1, '张三', 20, 'zhangsan@test.com', '2026-09-28 10:00:00');

2. 查：SELECT（查询数据）

-- 查询所有列（不推荐，数据量大时慢） SELECT * FROM users; -- 查询指定列（推荐） SELECT name, age FROM users; -- 列起别名（AS 可以省略） SELECT name AS 姓名, age 年龄 FROM users; -- 去重查询 SELECT DISTINCT age FROM users; -- 简单计算 SELECT name, age + 1 AS 明年年龄 FROM users;

3. 改：UPDATE（更新数据）

-- 更新某个人的年龄 UPDATE users SET age = 21 WHERE name = '张三'; -- 更新多个列 UPDATE users SET age = 23, email = 'new@test.com' WHERE id = 2; -- 所有人年龄 +1（慎用！没有 WHERE 会改全部） UPDATE users SET age = age + 1;

4. 删：DELETE（删除数据）

-- 删除某个人 DELETE FROM users WHERE id = 1; -- 删除符合条件的行 DELETE FROM users WHERE age > 30; -- 删除全部数据（危险！） DELETE FROM users; -- 清空表（更快，不记日志，不能回滚） TRUNCATE TABLE users;
UPDATE 和 DELETE 一定要加 WHERE！
忘记写 WHERE 会修改/删除整张表的数据。线上操作前先 SELECT 确认条件对不对，再执行更新/删除。

逻辑运算符

运算符说明示例

OR或者（满足一个就行）WHERE age < 18 OR age > 60
NOT不满足WHERE NOT age = 20

LIKE 模糊匹配

-- % 匹配任意多个字符（0个或多个） SELECT * FROM users WHERE name LIKE '张%'; -- 姓张的 SELECT * FROM users WHERE name LIKE '%三%'; -- 名字含"三"的 -- _ 匹配恰好一个字符 SELECT * FROM users WHERE name LIKE '张_'; -- 姓张且名字两个字 SELECT * FROM users WHERE name LIKE '张__'; -- 姓张且名字三个字

排序与分页

DQL

排序（ORDER BY）

-- 按年龄升序（默认就是升序，ASC 可省略） SELECT * FROM users ORDER BY age ASC; -- 按年龄降序 SELECT * FROM users ORDER BY age DESC; -- 多字段排序：先按年龄降序，年龄相同按 id 升序 SELECT * FROM users ORDER BY age DESC, id ASC;

分页（LIMIT）

-- 取前 N 条 SELECT * FROM users LIMIT 5; -- 前5条 -- 分页：LIMIT 偏移量, 每页条数 SELECT * FROM users LIMIT 0, 5; -- 第1页（前5条） SELECT * FROM users LIMIT 5, 5; -- 第2页（第6-10条） SELECT * FROM users LIMIT 10, 5; -- 第3页 -- 新写法（MySQL 8.0+）：LIMIT ... OFFSET ... SELECT * FROM users LIMIT 5 OFFSET 10; -- 跳过10条，取5条
分页公式
每页 N 条，第 page 页（从第1页开始）：
LIMIT (page - 1) * N, N

分组与聚合函数

面试必考

聚合函数

函数说明
COUNT(*)统计行数（忽略 NULL）
COUNT(col)统计某列不为 NULL 的行数
COUNT(DISTINCT col)去重后计数
SUM(col)求和
AVG(col)平均值
MAX(col)最大值
MIN(col)最小值
-- 基础聚合 SELECT COUNT(*) AS 总人数, SUM(age) AS 年龄总和, AVG(age) AS 平均年龄, MAX(age) AS 最大年龄, MIN(age) AS 最小年龄 FROM users;

GROUP BY 分组

-- 按年龄段分组，统计每组人数和平均年龄 SELECT age, COUNT(*) AS 人数, AVG(age) AS 平均年龄 FROM users GROUP BY age; -- 多字段分组 SELECT department, gender, COUNT(*) AS 人数 FROM employees GROUP BY department, gender; -- 分组 + 排序 SELECT age, COUNT(*) AS 人数 FROM users GROUP BY age ORDER BY 人数 DESC;

HAVING 分组后筛选

WHERE vs HAVING 的区别
WHERE：在分组之前筛选，不能用聚合函数
HAVING：在分组之后筛选，必须用聚合函数
执行顺序：WHERE → GROUP BY → 聚合计算 → HAVING
-- 找出人数大于1的年龄段 SELECT age, COUNT(*) AS 人数 FROM users WHERE age > 18 -- 先过滤：只要18岁以上的 GROUP BY age -- 再分组 HAVING COUNT(*) > 1 -- 再筛选：人数大于1的组 ORDER BY 人数 DESC; -- 再排序

多表连接（JOIN）

重点难点

实际项目中数据存在多张表里，需要把它们"连起来"查询。这就是 JOIN。

先建两张表演示

students 学生表

idnameclass_id
1张三101
2李四102
3王五101
4赵六NULL

classes 班级表

class_idclass_name
101计算机一班
102计算机二班
103软件工程班

四种 JOIN

类型说明结果
INNER JOIN 内连接：两边都匹配的才显示 张三+一班、李四+二班、王五+一班
LEFT JOIN 左连接：左边全部显示，右边匹配不到的为 NULL 张三+一班、李四+二班、王五+一班、赵六+NULL
RIGHT JOIN 右连接：右边全部显示，左边匹配不到的为 NULL 张三+一班、李四+二班、王五+一班、NULL+软工班
FULL JOIN 全连接：两边都显示（MySQL 不直接支持） 所有行都有
-- INNER JOIN（内连接，最常用） SELECT s.name, c.class_name FROM students s INNER JOIN classes c ON s.class_id = c.class_id; -- LEFT JOIN（左连接） SELECT s.name, c.class_name FROM students s LEFT JOIN classes c ON s.class_id = c.class_id; -- 三表连接 SELECT * FROM orders o JOIN users u ON o.user_id = u.id JOIN products p ON o.product_id = p.id;
JOIN 记忆技巧
把 LEFT JOIN 想成"以左表为准"：左表所有行都保留，右表能匹配上的就填数据，匹配不上的就填 NULL。
INNER JOIN 就是"两边都有才要"，两边都匹配不到的就丢弃。

子查询

进阶

子查询就是"查询里嵌套查询"，把一个 SELECT 的结果作为另一个查询的条件或来源。

-- 1. WHERE 中的子查询（标量子查询） -- 找出年龄最大的人 SELECT * FROM users WHERE age = (SELECT MAX(age) FROM users); -- 2. IN 子查询 -- 找出在一班的所有学生 SELECT * FROM students WHERE class_id IN ( SELECT class_id FROM classes WHERE class_name = '计算机一班' ); -- 3. FROM 中的子查询（派生表） SELECT AVG(s.age) FROM ( SELECT age FROM users WHERE age > 18 ) s; -- 4. EXISTS 子查询（存在性判断） -- 找出有学生的班级 SELECT * FROM classes c WHERE EXISTS ( SELECT 1 FROM students s WHERE s.class_id = c.class_id );
子查询 vs JOIN
很多子查询可以改写成 JOIN，通常 JOIN 效率更高。但子查询更直观、更好理解。初学者可以先用子查询，熟练了再考虑优化成 JOIN。
🔒

约束（Constraint）

数据完整性

约束是用来保证数据正确性和完整性的规则。

约束说明示例
PRIMARY KEY 主键：唯一且非空，每行的身份证 id INT PRIMARY KEY
AUTO_INCREMENT 自增（配合主键使用） id INT PRIMARY KEY AUTO_INCREMENT
NOT NULL 非空：不能不填 name VARCHAR(50) NOT NULL
UNIQUE 唯一：不能重复 email VARCHAR(100) UNIQUE
DEFAULT 默认值：不填时用这个 age INT DEFAULT 0
FOREIGN KEY 外键：关联另一张表的主键 FOREIGN KEY (class_id) REFERENCES classes(id)
CHECK 检查：自定义约束条件 age INT CHECK (age >= 0)
-- 带外键的建表示例 CREATE TABLE orders ( id INT PRIMARY KEY AUTO_INCREMENT, user_id INT NOT NULL, amount DECIMAL(10,2) DEFAULT 0, FOREIGN KEY (user_id) REFERENCES users(id) );

索引

性能优化

索引就像书的目录，能让你快速找到数据。没有索引就是一页一页翻（全表扫描），有索引就是翻目录找页码。

-- 查看索引 SHOW INDEX FROM users; -- 创建普通索引 CREATE INDEX idx_name ON users(name); -- 创建唯一索引 CREATE UNIQUE INDEX idx_email ON users(email); -- 创建复合索引（多列） CREATE INDEX idx_name_age ON users(name, age); -- 删除索引 DROP INDEX idx_name ON users; -- 查看执行计划（判断是否走索引） EXPLAIN SELECT * FROM users WHERE name = '张三';
索引使用原则
1. 经常出现在 WHERE 条件里的列建索引
2. 主键和唯一键自动有索引
3. 索引不是越多越好（写操作变慢、占空间）
4. 数据量小的表不需要索引
5. 用 EXPLAIN 查看是否走索引

事务（Transaction）

面试必考

事务就是一组 SQL 操作，它们要么全部成功，要么全部失败。最经典的例子就是银行转账：A 扣钱和 B 加钱必须同时成功，不能只扣不加。

-- 开启事务 START TRANSACTION; -- 执行操作 UPDATE account SET money = money - 100 WHERE name = 'A'; UPDATE account SET money = money + 100 WHERE name = 'B'; -- 如果都成功，提交 COMMIT; -- 如果出错了，回滚（撤销所有操作） ROLLBACK;

ACID 四大特性（面试必背）

A - 原子性（Atomicity）
事务是不可分割的最小单位，要么全成，要么全败。由 undo log 实现
C - 一致性（Consistency）
事务前后数据始终保持一致状态。比如转账前后总金额不变
I - 隔离性（Isolation）
多个事务互不干扰。有4种隔离级别
D - 持久性（Durability）
事务提交后永久生效，断电也不丢。由 redo log 实现

四种隔离级别

隔离级别脏读不可重复读幻读
读未提交（READ UNCOMMITTED）会会会
读已提交（READ COMMITTED）不会会会
可重复读（REPEATABLE READ）不会不会不会(MySQL)
串行化（SERIALIZABLE）不会不会不会
MySQL 默认隔离级别
MySQL InnoDB 引擎默认是 可重复读（REPEATABLE READ），并且通过 MVCC + Next-Key Lock 解决了幻读问题。这是面试高频题。

练习 4：分组与聚合

-- 1. 每个班有多少人 SELECT class, COUNT(*) AS 人数 FROM students GROUP BY class; -- 2. 数学成绩的平均分、最高分、最低分 SELECT AVG(s.score) AS 平均分, MAX(s.score) AS 最高分, MIN(s.score) AS 最低分 FROM scores s JOIN courses c ON s.course_id = c.id WHERE c.name = '数学'; -- 3. 每个学生的总分，按总分从高到低排 SELECT st.name, SUM(s.score) AS 总分 FROM scores s JOIN students st ON s.student_id = st.id GROUP BY st.id ORDER BY 总分 DESC; -- 4. 找出平均分大于85分的学生 SELECT st.name, AVG(s.score) AS 平均分 FROM scores s JOIN students st ON s.student_id = st.id GROUP BY st.id HAVING AVG(s.score) > 85 ORDER BY 平均分 DESC;

练习 5：子查询

-- 1. 找出数学成绩最高的学生 SELECT st.name, s.score FROM scores s JOIN students st ON s.student_id = st.id WHERE s.course_id = 1 AND s.score = (SELECT MAX(score) FROM scores WHERE course_id = 1); -- 2. 找出有不及格成绩的学生 SELECT DISTINCT st.name FROM students st WHERE EXISTS ( SELECT 1 FROM scores s WHERE s.student_id = st.id AND s.score < 60 );

面试高频问题速答

面试专用
问题参考回答
什么是主键？什么是外键？ 主键(PRIMARY KEY)：唯一标识一行记录，不能重复也不能为空。外键(FOREIGN KEY)：引用另一张表的主键，保证数据的参照完整性
DROP、DELETE、TRUNCATE 的区别？ DELETE：删除数据，保留表结构，可以回滚，可以加WHERE
TRUNCATE：清空表数据，保留表结构，不能回滚，更快
DROP：删除整个表（数据+结构都没了）
WHERE 和 HAVING 的区别？ WHERE 在分组前筛选，不能用聚合函数；HAVING 在分组后筛选，必须用聚合函数。执行顺序：WHERE → GROUP BY → 聚合 → HAVING
INNER JOIN 和 LEFT JOIN 的区别？ INNER JOIN：两边都匹配的行才显示；LEFT JOIN：左表全部显示，右表匹配不到的为NULL
什么是索引？有什么优缺点？ 索引像书的目录，加快查询速度。优点：查询快；缺点：占空间、降低写入速度（增删改要维护索引）
索引的底层数据结构？ B+树。B+树是多路平衡查找树，所有数据都在叶子节点，叶子节点用链表相连，适合范围查询
什么是事务？ACID 是什么？ 事务是一组要么全成功要么全失败的SQL操作。ACID：原子性(A)、一致性(C)、隔离性(I)、持久性(D)
事务的隔离级别有哪些？ 读未提交、读已提交、可重复读、串行化。级别越高越安全但性能越差。MySQL默认是可重复读
什么是脏读、不可重复读、幻读？ 脏读：读到了别的事务还没提交的数据
不可重复读：同一事务里两次读同一行，结果不一样（因为中间被改了）
幻读：同一事务里两次查询，行数不一样（因为中间插入了新行）
MySQL 存储引擎有哪些？区别？ InnoDB（默认）：支持事务、支持外键、行级锁
MyISAM：不支持事务、表级锁、速度快（读多写少场景）
现在基本都用 InnoDB
count(*), count(1), count(列名) 的区别？ count(*) 和 count(1)：统计总行数，结果一样，InnoDB 中性能差不多
count(列名)：统计该列不为 NULL 的行数，结果可能更少
什么是 SQL 注入？怎么防范？ SQL注入是通过输入恶意SQL代码来攻击数据库。防范：使用参数化查询（预编译语句），不要拼接SQL字符串
如何优化 SQL 查询？ 1. 给WHERE条件列加索引 2. 避免SELECT * 3. 用JOIN代替子查询 4. 避免索引失效（如左模糊匹配、列上做运算）5. 用EXPLAIN分析执行计划
什么情况下索引会失效？ 1. 索引列上做运算或函数 2. 隐式类型转换 3. LIKE左模糊(%开头) 4. OR连接的列没有索引 5. 违反最左前缀原则
最左前缀原则是什么？ 复合索引(index(a,b,c))从最左列开始匹配。WHERE a=1 AND b=2 走索引；WHERE b=2 AND c=3 不走索引（因为缺了a）
MySQL 为什么用 B+树而不用 B 树？ 1. B+树非叶子节点不存数据，能存更多索引项，树更矮，IO更少
2. B+树叶子节点用链表串联，范围查询更方便
3. B+树查询时间更稳定（每次都走到叶子节点）
什么是 MVCC？ 多版本并发控制（Multi-Version Concurrency Control）。每行数据有隐藏的版本号，读操作读的是快照版本，不用加锁，提高了并发性能。是 InnoDB 实现隔离级别的基础
