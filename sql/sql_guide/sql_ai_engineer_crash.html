Day 1 · 核心查询（SELECT 单表）

1.1 基础语法骨架

SELECT 列名1, 列名2, 计算列          -- 查什么
FROM 表名                            -- 从哪查
WHERE 行过滤条件                     -- 筛哪些行（分组前过滤）
ORDER BY 列名 DESC                   -- 怎么排
LIMIT 10;                            -- 取前几条

1.2 必会 8 个单表操作

场景SQL 模式记忆点
去重SELECT DISTINCT colDISTINCT 对整行去重，不是单列
条件筛选WHERE age > 18 AND city = '北京'AND 优先级高于 OR，用括号明确
模糊匹配WHERE name LIKE '张%'% 通配任意字符，_ 通配单个
范围/集合WHERE id IN (1,2,3) / BETWEEN 10 AND 20IN 相当于多个 OR
空值判断WHERE col IS NULL / IS NOT NULL不能用 = NULL，这是高频考点
排序ORDER BY col1 DESC, col2 ASC多列排序按优先级从左到右
限制条数LIMIT 10 OFFSET 20分页基础，OFFSET 跳过前 N 条
别名SELECT col AS new_nameAS 可省略，但建议写上可读性好

Day 2 · 聚合与多表（GROUP BY + JOIN）

2.1 聚合函数（配合 GROUP BY）

SELECT 
    department,                    -- 分组键
    COUNT(*) as emp_count,         -- 每组行数
    AVG(salary) as avg_salary,     -- 平均
    MAX(salary) as max_salary,     -- 最大
    MIN(salary) as min_salary,     -- 最小
    SUM(salary) as total_salary    -- 求和
FROM employees
WHERE hire_date > '2020-01-01'     -- ① 先过滤行（WHERE）
GROUP BY department                -- ② 再分组
HAVING AVG(salary) > 10000         -- ③ 再过滤组（HAVING）
ORDER BY avg_salary DESC           -- ④ 最后排序
LIMIT 5;
WHERE vs HAVING 的区别（面试必考）：WHERE 在分组前过滤行，HAVING 在分组后过滤组。WHERE 里不能用聚合函数（如 WHERE AVG(x) > 10 会报错），必须用 HAVING。

2.2 多表连接（JOIN）

类型结果使用场景
INNER JOIN只保留两表匹配的行默认，查"有对应关系"的数据
LEFT JOIN左表全保留，右表无匹配则为 NULL查"左表全部 + 右表可能有"（如：所有用户及其订单，没订单的显示 NULL）
RIGHT JOIN右表全保留少用，可用 LEFT JOIN 交换表顺序替代
FULL OUTER JOIN两表全保留MySQL 不支持，PostgreSQL 支持
-- 典型面试题：查询每个部门工资最高的员工
SELECT d.name as dept_name, e.name as emp_name, e.salary
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id
WHERE (e.dept_id, e.salary) IN (
    SELECT dept_id, MAX(salary)
    FROM employees
    GROUP BY dept_id
);

2.3 子查询三种位置

位置示例说明
WHERE 中WHERE salary > (SELECT AVG(salary) FROM emp)标量子查询，返回单个值
FROM 中FROM (SELECT dept, AVG(salary) as avg_s FROM emp GROUP BY dept) t派生表，必须起别名
SELECT 中SELECT name, (SELECT COUNT(*) FROM orders o WHERE o.user_id = u.id) as order_cnt FROM users u相关子查询，效率较低但直观
今日练习：LeetCode 181（Employees Earning More Than Their Managers）、182（Duplicate Emails）、183（Customers Who Never Order）、184（Department Highest Salary）、185（Department Top Three Salaries）。这 5 题覆盖 JOIN + GROUP BY + 子查询。

Day 3 · 实战场景（AI 工作流）

3.1 场景一：RAG 元数据过滤（pgvector）

假设你用 PostgreSQL + pgvector 存文档块，需要按条件过滤：

-- 建表（了解即可，一般用 ORM 或迁移工具）
CREATE TABLE documents (
    id SERIAL PRIMARY KEY,
    content TEXT,
    embedding VECTOR(1536),        -- pgvector 扩展
    source VARCHAR(100),           -- 来源
    created_at TIMESTAMP,
    category VARCHAR(50)
);

-- 语义检索 + 元数据过滤（RAG 核心查询）
SELECT content, source, 
       embedding <=> '[0.1, 0.2, ...]' as distance  -- 余弦距离
FROM documents
WHERE category = '技术文档'          -- 元数据过滤
  AND created_at > '2024-01-01'     -- 时间过滤
  AND source != '内部机密'           -- 安全过滤
ORDER BY embedding <=> '[0.1, 0.2, ...]'  -- 按向量相似度排序
LIMIT 5;                            -- Top-5 相关文档

3.2 场景二：数据分析（用户行为日志）

-- 统计每日活跃用户及平均使用时长（面试高频）
SELECT 
    DATE(login_time) as login_date,
    COUNT(DISTINCT user_id) as dau,
    AVG(session_duration) as avg_duration,
    COUNT(*) as total_sessions
FROM user_logs
WHERE login_time >= CURRENT_DATE - INTERVAL '30 days'
GROUP BY DATE(login_time)
HAVING COUNT(DISTINCT user_id) > 100
ORDER BY login_date DESC;

3.3 场景三：数据清洗（去重与窗口函数）

-- 保留每个用户最新的一条记录（ROW_NUMBER 窗口函数）
WITH ranked AS (
    SELECT *,
           ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY updated_at DESC) as rn
    FROM user_profiles
)
SELECT * FROM ranked WHERE rn = 1;

-- 计算每个用户与平均值的差距（窗口函数面试考点）
SELECT 
    user_id,
    score,
    AVG(score) OVER () as global_avg,           -- 全局平均
    AVG(score) OVER (PARTITION BY dept) as dept_avg,  -- 部门平均
    score - AVG(score) OVER (PARTITION BY dept) as diff_from_dept
FROM employee_scores;
窗口函数三件套（面试加分项）：
  • ROW_NUMBER()：去重取最新/最旧
  • RANK() / DENSE_RANK()：排名（允许并列）
  • LAG() / LEAD()：取前一行/后一行（计算环比）

SQL vs Pandas 对照表（AI 工程师视角）

操作SQLPandas (Python)何时用 SQL
筛选行WHERE age > 18df[df['age'] > 18]数据在数据库里，且只需要部分数据
选列SELECT name, agedf[['name', 'age']]同上
分组聚合GROUP BY deptdf.groupby('dept')数据量大（千万级），数据库引擎更快
表连接JOINpd.merge()两表都在数据库，避免先导出再合并
排序ORDER BYdf.sort_values()数据库索引排序通常更快
去重DISTINCTdf.drop_duplicates()数据库层去重减少传输量
复杂转换难写灵活（apply, map）简单转换用 SQL，复杂逻辑用 Python
决策原则：数据在数据库 → 先 SQL 过滤/聚合 → 导出小结果集 → Pandas 做复杂分析。不要全表导出再用 Python 筛（内存爆炸）。
