什么是 Docker

入门

Docker 是一个容器化平台，把应用和它的依赖打包到一个轻量、可移植的容器里，然后可以在任何 Linux/Windows/macOS 机器上运行。

一句话理解
Docker 解决了 "在我机器上能跑啊，怎么在你机器上就不行了？" 的世纪难题。
有了 Docker，你的应用 + 运行环境 + 配置全部打包在一起，到哪都能跑，而且环境完全一致。

容器 vs 虚拟机

对比项容器（Docker）虚拟机（VM）
体积小（MB 级）大（GB 级）
启动速度秒级分钟级
资源占用少（共享宿主机内核）多（每个都有完整 OS）
隔离性进程级隔离系统级隔离（更强）
性能接近原生有损耗
可移植性强，跨平台一致较强，但镜像大
应用 A | 应用 B | 应用 C
Docker 容器（每个有自己的依赖和运行时）
Docker 引擎
宿主机操作系统（共享内核）
物理硬件

容器架构（快、轻）

Docker 的核心优势

一致的运行环境
开发、测试、生产环境完全一样，再也没有"在我机器上能跑"的问题
快速部署
有镜像就能秒级启动容器，部署上线快得飞起
资源利用率高
一台机器可以跑几百个容器，比 VM 省多了
版本管理
镜像有版本号，可以回滚，可以追溯
微服务友好
每个微服务一个容器，隔离部署，互不影响
生态丰富
Docker Hub 上有几十万个现成镜像，拿来就用

三大核心概念

镜像（Image）
只读的模板，包含应用和运行环境。
类比：软件安装包 / 类（class）
一个镜像可以创建多个容器
容器（Container）
镜像运行的实例，可读写。
类比：安装好的软件 / 对象（instance）
容器之间互相隔离
仓库（Repository）
存放镜像的地方。
类比：应用商店 / GitHub
Docker Hub 是最大的公共仓库
镜像 vs 容器
就像面向对象里的 类和对象：
镜像是类（模板），容器是对象（实例）。
一个类可以 new 很多对象，一个镜像可以创建很多容器。

安装与配置

入门

Windows 安装 Docker Desktop

  1. 去官网下载 Docker Desktop for Windows
  2. 双击安装，勾选 "Use WSL 2 instead of Hyper-V"
  3. 安装完成后重启电脑
  4. 打开 Docker Desktop，等待启动完成
  5. 打开 cmd 或 PowerShell，输入 docker --version 验证
WSL2 后端推荐
Docker Desktop 推荐用 WSL2 后端，比 Hyper-V 更快、资源占用更少。
在 Docker Desktop → Settings → General 里确认 "Use the WSL 2 based engine" 已勾选。

配置镜像加速（国内必做！）

默认从 Docker Hub 拉镜像很慢，配置国内镜像站：

// Docker Desktop → Settings → Docker Engine // 在 JSON 里添加 registry-mirrors： { "registry-mirrors": [ "https://docker.mirrors.ustc.edu.cn", "https://hub-mirror.c.163.com", "https://mirror.baidubce.com" ] } // Apply & restart 重启生效

验证安装

# 查看版本 docker --version docker version # 更详细 # 运行 hello-world 测试 docker run hello-world # 看到 "Hello from Docker!" 就说明装好了

开启 WSL2 集成

在 Docker Desktop → Settings → Resources → WSL Integration 里，把你的 Ubuntu-22.04 开关打开。这样你在 WSL 里也能用 docker 命令。

核心概念详解

基础

镜像（Image）

镜像是分层的。每一条 Dockerfile 指令创建一层，每层都是只读的。容器在最上面加了一层可写层。

// 镜像分层示例： ┌─────────────────────┐ │ 可写层（容器层） │ ← 只有容器有，可读写 ├─────────────────────┤ │ 应用代码层 │ ← 镜像层，只读 ├─────────────────────┤ │ 依赖库层 │ ← 镜像层，只读 ├─────────────────────┤ │ 操作系统基础层 │ ← 镜像层，只读 └─────────────────────┘ // 好处：多个镜像可以共享底层，节省空间 // 比如两个都用 Ubuntu 基础镜像的应用，只存一份 Ubuntu

容器（Container）

容器是镜像的运行实例。每个容器有自己的：

  • 文件系统（在镜像上加一层可写层）
  • 进程空间（独立的 PID）
  • 网络空间（独立的 IP 和端口）
  • 用户空间（独立的用户）
注意：容器里的数据不持久！
容器被删除时，可写层的数据也会一起删掉。
需要持久化的数据要用 数据卷（Volume） 或 挂载目录。

容器的生命周期

docker create 创建（不启动） docker start 启动 docker run 创建并启动（常用！） docker pause 暂停 docker unpause 恢复 docker stop 停止（优雅退出，发 SIGTERM，等10秒再 SIGKILL） docker kill 强制停止（直接 SIGKILL） docker restart 重启 docker rm 删除（先停止才能删，加 -f 强制删） // 状态：created → running → paused → stopped → deleted

仓库（Registry）

Docker Hub
官方公共仓库，镜像最全，国内访问慢
阿里云镜像仓库
国内速度快，个人版免费
腾讯云镜像仓库
国内速度快，有免费额度
私有仓库
公司内部用，用 Harbor 或 registry 自建

Dockerfile 镜像构建

重点

Dockerfile 是一个文本文件，里面写了构建镜像的一条条指令。Docker 照着它就能自动构建镜像。

常用指令

指令作用说明
FROM基础镜像第一条指令，指定基于哪个镜像构建
MAINTAINER作者信息已过时，用 LABEL 代替
LABEL元数据添加镜像标签（作者、版本、描述等）
RUN执行命令构建时执行，每一个 RUN 会创建新层
CMD启动命令容器启动时执行的默认命令，docker run 后面有命令会覆盖
ENTRYPOINT入口命令容器启动时执行，不会被 run 的命令覆盖（会当参数传进去）
EXPOSE暴露端口声明容器监听的端口（只是声明，实际 -p 才映射）
ENV环境变量设置环境变量，构建和运行时都能用
ARG构建参数只在构建时有效，build --build-arg 传参
ADD复制文件复制到镜像里，tar 自动解压，支持 URL
COPY复制文件普通复制，推荐用这个（更透明）
VOLUME匿名卷声明挂载点，自动创建数据卷
WORKDIR工作目录设置当前工作目录（类似 cd）
USER用户指定运行命令的用户
HEALTHCHECK健康检查定时检查容器是否健康
ONBUILD触发器当这个镜像被当作基础镜像时执行

示例：Node.js 应用的 Dockerfile

# 1. 基础镜像 FROM node:18-alpine # 2. 元数据 LABEL maintainer="geist@example.com" LABEL version="1.0" # 3. 工作目录（后面的命令都在这个目录下执行） WORKDIR /app # 4. 先复制依赖文件（利用缓存，依赖没变就不用重装） COPY package*.json ./ # 5. 安装依赖 RUN npm install --production && npm cache clean --force # 6. 复制应用代码 COPY . . # 7. 暴露端口 EXPOSE 3000 # 8. 健康检查 HEALTHCHECK --interval=30s --timeout=3s \ CMD curl -f http://localhost:3000/health || exit 1 # 9. 启动命令 CMD ["node", "app.js"]

构建命令

# 在 Dockerfile 所在目录构建 docker build -t myapp:v1 . # -t 给镜像打标签（名字:版本） # . 表示当前目录（构建上下文） # 指定 Dockerfile 路径 docker build -f ./docker/Dockerfile -t myapp:v1 . # 传构建参数 docker build --build-arg APP_ENV=production -t myapp:v1 . # 不使用缓存（强制重新构建） docker build --no-cache -t myapp:v1 .

.dockerignore 文件

和 .gitignore 类似，告诉 Docker 构建时哪些文件不要打包进上下文：

node_modules npm-debug.log .git .gitignore .env *.md .vscode .idea __pycache__ *.pyc .DS_Store

Dockerfile 最佳实践

1. 选合适的基础镜像
优先用 alpine 版本（体积小），能用官方镜像就别自己做
2. 减少层数
多个 RUN 命令用 && 连起来写成一条，减少镜像层数
3. 利用缓存
把不常变的（依赖安装）放前面，常变的（代码）放后面
4. 用 COPY 不用 ADD
除非你需要自动解压或从 URL 下载，否则用 COPY 更明确
5. 多阶段构建
编译阶段和运行阶段分开，最终镜像只包含运行时需要的东西
6. 用 .dockerignore
忽略 node_modules、.git 等，减少上下文大小
7. 不要用 latest
生产环境指定具体版本号，latest 不稳定
8. 不要以 root 运行
创建普通用户，用 USER 指令切换，更安全

多阶段构建示例

# 构建阶段：有完整编译环境 FROM golang:1.21 AS builder WORKDIR /app COPY . . RUN go build -o myapp . # 运行阶段：只有运行时，镜像很小 FROM alpine:3.18 WORKDIR /app COPY --from=builder /app/myapp . CMD ["./myapp"] // 最终镜像里没有 Go 编译器，只有编译好的二进制，体积大大减小

数据卷（Volume）

重点

为什么需要数据卷？

容器的文件系统是临时的，容器删了数据就没了。数据卷可以：

  • 持久化数据：容器删了数据还在
  • 共享数据：多个容器可以共享同一个数据卷
  • 配置文件：把配置文件挂载进去，不用改镜像
  • 日志输出：容器日志直接写到宿主机

三种挂载方式

方式语法说明场景
匿名卷-v /dataDocker 自动创建和管理，不知道在哪临时数据、不需要手动管理
具名卷-v myvol:/data有名字，Docker 管理，可以重复用推荐！持久化数据
绑定挂载-v /host/path:/data挂载宿主机的具体目录配置文件、开发时代码同步

数据卷命令

# 创建卷 docker volume create myvolume # 查看所有卷 docker volume ls # 查看卷详情 docker volume inspect myvolume # 删除卷 docker volume rm myvolume # 清理无用的卷 docker volume prune # 使用卷 docker run -d -v myvolume:/data nginx # -v 卷名:容器内路径 # 绑定挂载（指定宿主机路径） docker run -d -v /home/user/data:/data nginx docker run -d -v ./data:/data nginx # 相对路径 # 只读挂载 docker run -d -v myvolume:/data:ro nginx # :ro = read only，容器里只能读不能改

示例：MySQL 数据持久化

# 不挂载数据卷：容器删了数据就没了 docker run -d --name mysql -e MYSQL_ROOT_PASSWORD=123456 mysql:8.0 # 挂载数据卷：容器删了数据还在 docker run -d --name mysql \ -e MYSQL_ROOT_PASSWORD=123456 \ -v mysql_data:/var/lib/mysql \ mysql:8.0 # mysql_data 是具名卷，数据存在 Docker 管理的目录里 # 就算删掉容器，重新创建时挂同一个卷，数据就回来了
注意：挂载空卷到有数据的目录
如果你把一个空的卷挂载到容器里一个有数据的目录，
Docker 会把容器里那个目录里的内容复制到卷里，然后再挂载。
但如果是绑定挂载（宿主机目录），就是直接覆盖，宿主机目录是什么样就是什么样。

Docker 网络

进阶

网络模式

模式说明特点
bridge桥接模式（默认）每个容器有独立IP，通过网桥和宿主机通信，容器之间可以互相访问
host主机模式容器和宿主机共用网络，没有隔离，性能好，但端口不能冲突
none无网络容器没有网络，完全隔离
container容器模式和另一个容器共享网络栈（共用 IP 和端口）

网络命令

# 查看所有网络 docker network ls # 查看网络详情 docker network inspect 网络名 # 创建网络 docker network create mynetwork docker network create --driver bridge mynetwork # 删除网络 docker network rm 网络名 # 清理无用网络 docker network prune # 把容器连接到网络 docker network connect 网络名 容器名 # 把容器从网络断开 docker network disconnect 网络名 容器名 # 启动容器时指定网络 docker run -d --name c1 --network mynetwork nginx docker run -d --name c2 --network mynetwork nginx # c1 和 c2 在同一个自定义网络里，可以用名字互访

容器间通信

# 方式1：通过 IP 访问（不推荐，IP 会变） docker inspect c1 | grep IPAddress # 查 IP # 然后 c2 里用 IP 访问 c1 # 方式2：自定义网络 + 容器名访问（推荐！） docker network create mynet docker run -d --name web --network mynet nginx docker run -d --name app --network mynet myapp # 在 app 容器里直接用 http://web:80 就能访问 web 容器 # 方式3：--link（已过时，不推荐） docker run -d --name app --link web:web myapp
推荐做法
1. 每个项目创建一个自定义网络
2. 相关的容器都加入这个网络
3. 容器之间用容器名互相访问
4. 只有需要对外暴露的端口才用 -p 映射

端口映射

# 格式：-p 主机端口:容器端口 docker run -d -p 8080:80 nginx # 访问主机的 8080 端口 → 转发到容器的 80 端口 # 指定绑定 IP（只允许本机访问） docker run -d -p 127.0.0.1:8080:80 nginx # 映射多个端口 docker run -d -p 8080:80 -p 443:443 nginx # 随机端口（宿主机随机分配） docker run -d -P nginx # 查看端口映射 docker port 容器名

Docker Compose

重点

什么是 Docker Compose？

一个应用往往需要多个容器（比如 Web + MySQL + Redis）。一个一个启动太麻烦了。Docker Compose 让你用一个 YAML 文件定义所有容器，一条命令就能全部启动/停止。

docker-compose.yml 示例

version: '3.8' services: # Web 服务（Nginx） web: image: nginx:alpine ports: - "8080:80" volumes: - ./html:/usr/share/nginx/html depends_on: - app networks: - mynet restart: always # 应用服务（Node.js） app: build: ./app # 从 Dockerfile 构建 image: myapp:v1 environment: - NODE_ENV=production - DB_HOST=mysql - DB_PASSWORD=123456 depends_on: - mysql - redis networks: - mynet restart: always # MySQL 数据库 mysql: image: mysql:8.0 environment: - MYSQL_ROOT_PASSWORD=123456 - MYSQL_DATABASE=myapp volumes: - mysql_data:/var/lib/mysql networks: - mynet restart: always # Redis 缓存 redis: image: redis:alpine volumes: - redis_data:/data networks: - mynet restart: always # 数据卷（services 里用的具名卷要在这里声明） volumes: mysql_data: redis_data: # 自定义网络 networks: mynet: driver: bridge

常用命令

# 启动所有服务（后台运行） docker-compose up -d docker compose up -d # 新版 Docker 用 docker compose（没有横杠） # 停止并删除 docker-compose down # 停止（不删除） docker-compose stop # 启动已停止的 docker-compose start # 重启 docker-compose restart # 查看状态 docker-compose ps # 查看日志 docker-compose logs docker-compose logs -f docker-compose logs web # 只看某个服务 # 重新构建镜像 docker-compose build docker-compose up -d --build # 构建并启动 # 进入某个服务的容器 docker-compose exec web /bin/sh # 指定 compose 文件 docker-compose -f docker-compose.dev.yml up -d # 拉取所有镜像 docker-compose pull
depends_on 的注意事项
depends_on 只保证启动顺序，不保证服务就绪。
比如 MySQL 启动了，但还没初始化完，这时候应用连上去会报错。
解决方法：1. 应用里加重试机制 2. 用 healthcheck + condition

最佳实践

进阶

镜像构建最佳实践

镜像要小
用 alpine 基础镜像、多阶段构建、清理缓存（apt clean 等）
构建要快
合理安排 Dockerfile 顺序，利用缓存；用 .dockerignore 减少上下文
不要在镜像里存密码
敏感信息用环境变量或 secrets，不要写死在 Dockerfile 里
一个容器一个进程
每个容器只跑一个主进程，多个服务就起多个容器
不要用 root
创建普通用户，用 USER 指令切换，安全第一
打标签不用 latest
用版本号（v1.0.0）或 git commit id，方便回滚

容器运行最佳实践

数据放卷里
数据库、用户上传等需要持久化的数据，一定要用 Volume
设置 restart
生产环境用 restart: always 或 unless-stopped，服务挂了自动重启
限制资源
用 --memory 和 --cpus 限制容器资源，防止一个容器吃光所有资源
只暴露必要端口
只把需要对外的端口映射出来，内部通信走自定义网络
健康检查
加 HEALTHCHECK，Docker 自动检测容器是否健康，不健康就重启
日志管理
不要把日志写在容器文件里，用 stdout/stderr 输出，Docker 统一管理

安全最佳实践

  • 用官方镜像，不要随便用不知名的镜像
  • 定期更新基础镜像，修复安全漏洞
  • 用 docker scan 或 trivy 扫描镜像漏洞
  • 不要用 --privileged（特权模式），除非真的需要
  • 容器以非 root 用户运行
  • 用 Docker Content Trust 验证镜像签名

面试高频问题速答

面试专用
问题参考回答
什么是 Docker？和虚拟机的区别？ Docker 是容器化平台，把应用和依赖打包到轻量可移植的容器里。
和 VM 比：容器共享宿主机内核，体积小（MB级）、启动快（秒级）、性能接近原生；VM 有完整操作系统，体积大（GB级）、启动慢、有性能损耗。容器是进程级隔离，VM 是系统级隔离。
镜像和容器的区别？ 镜像是只读模板（类比类），容器是镜像运行的实例（类比对象）。一个镜像可以创建多个容器。镜像分层存储，容器在镜像上加了一层可写层。
Docker 的底层原理？ 主要用了 Linux 的三个核心技术：
1. Namespace（命名空间）：实现隔离（PID、NET、IPC、UTS、Mount、User）
2. Cgroups（控制组）：限制和隔离资源使用（CPU、内存、IO）
3. UnionFS（联合文件系统）：实现镜像分层和写时复制
什么是容器的写时复制（CoW）？ 镜像分层，所有层都是只读的。容器启动时在最上面加一层可写层。当要修改文件时，才把文件从下面的只读层复制到可写层再修改。没修改的文件大家共享，节省空间。
Dockerfile 中 COPY 和 ADD 的区别？ 都能复制文件到镜像。ADD 额外支持：1. 自动解压 tar 文件 2. 从 URL 下载文件。
一般推荐用 COPY，更明确。需要解压或下载时才用 ADD。
CMD 和 ENTRYPOINT 的区别？ 都是容器启动时执行的命令。
CMD 会被 docker run 后面的命令覆盖；ENTRYPOINT 不会被覆盖（而是把命令当参数传给它）。
一般 ENTRYPOINT 用来定死启动命令，CMD 用来给默认参数。
数据卷有几种方式？ 三种：
1. 匿名卷：-v /path，Docker 自动管理
2. 具名卷：-v name:/path，有名字，推荐用于持久化
3. 绑定挂载：-v /host/path:/path，挂载宿主机具体目录
另外还有 tmpfs 挂载（内存里，临时数据）
Docker 网络模式有哪些？ bridge（默认，桥接，各容器独立IP）、host（共用宿主机网络）、none（无网络）、container（共享另一个容器的网络）。
生产环境一般用自定义 bridge 网络，容器之间用名字互访。
容器之间怎么通信？ 1. 同一网络下通过容器名/服务名访问（推荐）
2. 通过容器 IP 访问（不推荐，IP 会变）
3. 通过宿主机 IP + 端口映射（绕一圈，不推荐）
4. --link（已过时）
什么是 Docker Compose？ 用于定义和运行多容器 Docker 应用的工具。用一个 YAML 文件配置所有服务，一条命令就能启动/停止整个应用栈。适合开发环境和小型部署。
怎么减少 Docker 镜像体积？ 1. 用 alpine/slim 基础镜像
2. 多阶段构建（编译和运行分开）
3. 合并 RUN 指令，减少层数
4. 安装完清理缓存（apt clean, npm cache clean）
5. .dockerignore 排除不必要的文件
容器退出了怎么排查？ 1. docker ps -a 看退出状态码
2. docker logs 容器名 看日志
3. docker inspect 容器名 看详细信息（OOMKilled、ExitCode等）
4. docker start -i 容器名 交互模式启动看输出
什么是 OOMKilled？ 容器使用内存超过了限制，被系统 OOM killer 杀掉了。Exit Code 是 137。解决方法：优化程序内存使用，或增加内存限制。
Docker 怎么实现资源限制？ 用 Cgroups。常用参数：
--memory：限制内存使用
--cpus：限制 CPU 核心数
--cpu-shares：CPU 相对权重
--blkio-weight：IO 权重
Kubernetes 和 Docker 的关系？ Docker 是容器运行时，负责单个容器的创建和管理。K8s 是容器编排平台，管理成百上千个容器，负责调度、伸缩、负载均衡、自愈等。Docker 是 K8s 下面的容器运行时之一。
